# Security Policy

Внутренний проект (учёт сырья и производства для мыловарни), закрытый репозиторий,
без публичной регистрации внешних пользователей вне компаний-тенантов приложения.

## Сообщить об уязвимости

Написать разработчику напрямую (Александр) — не создавать публичный Issue с деталями
уязвимости. Внутри самого приложения есть форма «Обратная связь» (`/feedback`, любая
авторизованная роль) — подходит для мелких находок, для критичных уязвимостей — писать
напрямую в обход очереди.

## Что уже применяется

- Пароли — только bcrypt-хэш (`app/security.py`), plaintext нигде не хранится.
- JWT-секрет — только из `JWT_SECRET` (env), приложение отказывается стартовать на Render
  без него (`app/config.py`).
- Ролевой доступ проверяется на каждом роутере (`require_roles`), не только скрытием
  пункта меню на фронте.
- Мультитенантность — все запросы фильтруются по `company_id`, кросс-компанийный доступ
  по id — всегда 404.
- Rate-limit на публичных/дорогих эндпоинтах (регистрация, обратная связь).
- Загрузка файлов (скриншоты в форме обратной связи) — перекодируется в чистый PNG,
  проверка на decompression bomb, лимиты размера/разрешения/имени файла.
- `/code-review` и `/security-review` — перед каждым пушем на прод (правило Founder,
  см. `CLAUDE.md`), не разово по запросу.
- Dependabot (`.github/dependabot.yml`) — еженедельные алерты по уязвимым зависимостям
  (pip/npm/actions).

## Известные, осознанно не устранённые пробелы

- MFA/2FA — не реализовано (небольшая команда, доступ ограничен ролями и сетью мастерской
  для worker'ов).
- Формальный CI-гейт с обязательным code review/branch protection — не настроен; вместо
  этого используется ручной `/code-review`+`/security-review` перед каждым пушем (см.
  `CLAUDE.md` → Testing) — осознанная альтернатива для команды из 1-2 разработчиков.
- Полное удаление персональных данных пользователя (GDPR "right to erasure") — не
  реализовано, увольнение сотрудника переводит статус в «уволен» (soft-delete), не удаляет
  запись физически.

PCI-DSS/HIPAA не применимы — приложение не обрабатывает платёжные карты и не хранит
медицинские данные.
